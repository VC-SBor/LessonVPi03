# VK-бот с AI-помощником (ProxyAPI)

Бот на [VKBottle](https://vkbottle.readthedocs.io/ru/latest/) работает через **Long Poll API**, умеет:

- **приветствовать новых участников**, вошедших в беседу (`chat_invite_user` / `chat_invite_user_by_link`);
- **отвечать на входящие сообщения** с помощью AI через провайдер [ProxyAPI](https://proxyapi.ru/docs/openai-text-generation), модель `gpt-4.1-mini`.

Ключи хранятся в `.env` и читаются модулем `python-dotenv`.

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | Точка входа: бот, хендлеры (приветствие + AI), запуск LongPoll |
| `ai_client.py` | Клиент ProxyAPI (`/v1/chat/completions`) + история диалогов |
| `config.py` | Загрузка и проверка настроек из `.env` |
| `.env` | Ваши ключи (**не коммитить**, шаблон — `.env.example`) |
| `requirements.txt` | Зависимости: `vkbottle`, `python-dotenv`, `aiohttp`, `loguru` |
| `docs/` | Локальная копия документации VKBottle (собрана с сайта) |

## Настройка

### 1. Зависимости

В проекте уже есть venv (Python 3.12):

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

> `loguru` в списке не случайно: без него vkbottle переключается на встроенный фолбэк-логгер, у которого нет метода `.opt`, и при первой же ошибке в задаче бот падает с `AttributeError` вместо записи ошибки в лог.

### 2. Ключи в `.env`

```dotenv
VK_TOKEN=...        # токен сообщества
PROXYAPI_KEY=...    # ключ API ProxyAPI
```

- Токен сообщества: **Управление сообществом → Рабочий стол → Работа с API → Ключи доступа** (прав «сообщения» достаточно).
- Ключ ProxyAPI: <https://console.proxyapi.ru> → раздел «API-ключи».

### 3. Настройки сообщества

- Включите **Long Poll API** в настройках «Работа с API»;
- поставьте галочки на нужных событиях (для бота — **входящие сообщения**);
- включите сообщения сообщества и выдайте боту доступ к беседам, где он должен приветствовать.

## Запуск

```powershell
.\venv\Scripts\python.exe main.py
```

При отсутствии ключей бот завершится с понятным сообщением, какую переменную заполнить.

## Как это работает

### Приветствие

```python
@bot.on.chat_message(action=["chat_invite_user", "chat_invite_user_by_link"])
async def greet_new_user(message: Message): ...
```

Параметр `action` — встроенное правило `ChatActionRule` (см. `docs/03-handling.md`). Имя нового участника получаем через `bot.api.users.get`, в тексте упоминаем его как `[id{member_id}|{name}]`. События с отрицательным `member_id` (добавление групп/ботов) пропускаются.

### AI-ответы

Запрос уходит на `POST https://api.proxyapi.ru/v1/chat/completions` в формате OpenAI:

- заголовок `Authorization: Bearer <PROXYAPI_KEY>`;
- тело: `{"model": "gpt-4.1-mini", "messages": [...]}`;
- ответ читается из `choices[0].message.content`.

Модель не помнит переписку между запросами, поэтому `ai_client.ProxyAIClient` хранит историю каждого диалога (`peer_id`) и отправляет её заново; старые реплики обрезаются по `AI_HISTORY_LIMIT` (по умолчанию 10 пар). При ошибке API пользователь видит вежливое «попробуйте позже», а история не ломается.

Хендлер `@bot.on.message(length=1)` реагирует только на непустой текст (пустые события-действия вроде выхода из беседы игнорируются), он зарегистрирован после приветствия, поэтому их порядок безопасен.

### Длинные ответы

`message.answer()` во vkbottle сам разбивает длинный текст на части по лимиту ВК, отдельная обрезка не нужна.

## Примечания

- **Запуск**: на сайте документации описан `bot.run_forever()`; в установленной версии vkbottle 4.11 он помечен устаревшим, поэтому используется актуальный `bot.run()` (эквивалентен, без предупреждений).
- **Модель**: для `/v1/chat/completions` короткое имя `gpt-4.1-mini` автоматически дополняется до `openai/gpt-4.1-mini`; полную запись можно прописать в `AI_MODEL` — по документации она надёжнее ([модели ProxyAPI](https://proxyapi.ru/docs/models)).
- **Юзербот**: используется только токен сообщества, т.к. юзерботы нарушают [правила ВК](https://vk.ru/terms) (см. `docs/02-high-level-bot.md`).
- Лимиты ВК на частоту запросов: при массовых рассылках учитывайте [ошибку №6 / rate limit](docs/04-low-level-api.md).

## Тестирование без VK

Полная логика проверяется офлайн: `ai_client` указывается на локальный HTTP-сервер, имитирующий ProxyAPI, а события моделируются словарями в формате LongPoll.
